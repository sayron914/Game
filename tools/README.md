# Инструменты проверки

Аналог `tools/` из Claude-of-Duty, приспособленный под нашу игру.
Ключевая идея оттуда: **медиана скрывает проблему, смотреть надо на хвост
распределения и на воспроизводимость.**

| скрипт | что ловит |
|---|---|
| `sim-headless.mjs` | цикл разорван, смертность, деньги некуда тратить, лут не падает |
| `render-check.mjs` | NaN в координатах, битые цвета, p95/p99 по операциям, лишние перестроения DOM |
| `balance-sweep.mjs` | одинаковые исходы у разных стилей (решений нет) или доминирующая стратегия |
| `text-audit.mjs` | когда игрок увидит первый повтор события |
| `check-all.mjs` | всё сразу, ненулевой код возврата при предупреждениях |

```
node check-all.mjs путь/к/игре.html
```

## Почему именно эти проверки

- **Хвост, а не медиана.** У Claude-of-Duty статичный бенчмарк показывал 94 fps,
  а игра шла на 12–17 с паузами по секунде. `render-check` печатает p50/p95/p99.
- **Воспроизводимость.** Там оказалось, что съёмка кадров не повторяется между
  запусками из-за утечки состояния. У нас аналог — `render-check` гоняет
  фиксированное число кадров с фиксированным шагом времени.
- **Проверять надо поведение, а не только код.** `node --check` ловит синтаксис,
  но не ловит пустую доску контрактов и не ловит, что клики не доходят.

## Что переносится в Godot

`sim-headless` и `balance-sweep` — один в один: класс симуляции не знает про
отрисовку, поэтому запускается из консольного проекта или из юнит-теста.
`render-check` заменяется на съёмку кадров через `--headless` плюс попиксельное
сравнение с эталоном.
